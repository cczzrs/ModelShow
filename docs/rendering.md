# 场景与渲染

[返回项目入口](../README.md) · [操作说明](usage.md)

## 两类 GPU 职责

ModelShow 将计算与展示分开：

| 职责 | 平台 | 语义 |
| --- | --- | --- |
| EX 计算 | JavaScript，或可选 WebGPU compute | 按 JKRD7 §7.5 计算合格批，按串行顺序提交 |
| 网络场景 | Three.js WebGPU，失败时 Canvas 2D | 显示结构、连接和当前 q，不调度模型 |
| JKM 输出位画板 | Canvas 2D | 显示真实输出事件已读取的位 |
| RGB 灯阵 | 原 Three.js／Canvas 场景与颜色预览 | 按观察位和通道配置显示 RGB，不改写模型 |

模型管理中的“计算平台”和页脚“渲染状态”分别报告两类状态。场景 GPU 工作不代表 EX 已在 GPU 计算；Canvas 场景降级也不改变 q、队列或执行记录。不使用 CUDA 或 WebGL 计算路径。

## 保留原页面与 3D 外观

页面沿用 JK OBSERVATORY 原来的顶栏、左右侧栏、中央场景、节点选择条和播放条；原 CSS 布局、配色、间距与对话框风格保留。header-center 底部增加 RGB／JKM 标签，默认 JKM。RGB 使用完整的原输入图片、RGB 输出和模型管理窗口；JKM 保留当前窗口。两者拥有独立场景和运行状态，切换时暂停并保留现场。

场景沿用此前的立方体节点、六面明暗、粉色 J／蓝色 K 曲线、箭头、曲线缓慢漂移、选中高亮、节点名称和计算次数。保留网格、纯黑背景开关、Trackball／EditorControls 操作及 Canvas 降级效果。

节点内部的 `x` 标记仅在该 JKI 存在 `sources` 且 `sources.ex` 非空时显示；缺失或空 EX 不显示标记。该条件与 q 的 0／1 值无关，观察端点不显示标记。

模型通过纯展示适配器进入原场景。每个 JKI 仍使用真实绝对路径，输入入口也是 JKI；观察端点以 `observe:` 标识，只用于展示。J／K 取值连接和 trigger 通知连接分开记录：通知动画使用标记，EX 读取动画才显示实际读取的位。展示适配不增加 Xi／Yi 执行规则，不修改模型或标准执行记录。

## 布局与操作

| 布局 | 保留的布局方式 |
| --- | --- |
| 1D | 各类节点沿 Y 轴排列 |
| 2D | YZ 平面排列 |
| 3D | 近似立方体展开 |
| 4D | 按网络拓扑安排空间位置 |
| 5D（默认） | 保留输入／输出边界，从中心向外扩张并优化引用距离 |
| 自动 | 比较遮挡、交叉和连线长度后选择布局 |

这些名称表示原有可视化布局，不增加计算维度，也不改变执行顺序。左拖旋转，右键／中键／Shift+左键平移，滚轮围绕鼠标位置缩放；保留重置视角、显示名称和次数、纯黑背景与全屏按钮。

播放条恢复速度倍率和“跳过动画”。取消跳过后按速度显示逐单元信号，单步也显示信号；事务仍作为完整处理单元执行，动画不拆分其提交边界。

## JKM 输出位画板

JKM 输出位画板按输出事件排列位行，列序严格遵守 observe.read。只在 watch 通知投递后添加一行；事务内通知在提交后投递。绿色表示 1，灰色表示 0，未输出保持等待。可见行数是展示限制，不修改输出的计算顺序。

模型定义、运行脚本与现场快照分别保存。输出观察和画板属于接入／展示模块，不在 JKM 中增加布局、颜色或灯绑定字段。

## RGB 输出渲染

RGB 保留原 3D 灯阵效果：输出侧的平面 RGB 灯、黑色框体、细边框及观察连接。窗口支持行列和尺寸、固定通道亮度、分通道／打包位绑定、位序调整与批量填充。预览显示同一份通道配置的计算结果。

默认 `RGB_3X3` 的 216 个观察位按逐像素 RGB、每通道 8 位、LSB 优先绑定到 3×3 灯阵；显示开关沿用原来的关闭默认值。勾选“显示画板”才在网络场景中显示灯阵。完成节点等待整帧后发布通知，画板只读取真实输出，不把初始化或重新布局当作输出。

灯阵绑定使用 JKI 绝对路径，场景适配时映射到 `observe:` 展示端点。用户配置单独保存在 `.rgb.json`，包含输入／观察绑定与 `display`；不会修改 JKM、q、FIFO 或标准记录。同一页面按模型与绑定缓存灯阵，跨页面恢复需导入配置文件。

## 验证边界

真实 WebGPU 初始化、计算、设备行为和 Canvas 降级必须在外部 Chrome 验证。Node.js 中的异步计算回调对拍只证明调度与记录一致，不能代替真实 GPU。验收截图与过程报告放在系统临时目录，并保留原日期、平台、覆盖范围及未验证事项；未记录的路径不视为已验证。正式测试源码保留在 `tests/`，产品文档保留在 `docs/`，详见[留档管理](development.md#留档管理)。
