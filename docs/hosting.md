# 共享模型池与托管

[返回项目入口](../README.md) · [开发维护](development.md)

## 模型管理

“模型管理”窗口按顺序提供“导入模型：选择 JSON 文件”、模型池下拉框、“入池”和“删除”。下拉框分为永久模型与临时模型两组，每组按时间从新到旧排列，选择后立即加载场景，并在 JSON 输入区显示原始模型。首次加载默认选择 `promotedAt` 最新的永久模型；没有永久模型时选择最新临时模型，两组都为空时显示空网络。同一时间以数组中靠后的条目为新。

- 窗口左下角的“下载模型”保存完整模型 JSON。下载当前已加载模型时，与“导出模型及画板配置”共用导出逻辑，将当前 `outputDisplay`（显示开关、行列数、画板大小、灯及通道绑定、位序与亮度换算）一起保存；关闭画板也保留配置。以模型名称作为文件名，保留其它原字段、ID 写法和 MD5，不包含模型池外层结构。若编辑区内容已修改但尚未导入，则保留草稿自身的渲染配置，避免套用另一模型的画板。空内容或无效模型不会生成文件。下载无需后端或管理员口令，也不会改变当前计算状态。
- 所有人可查看和使用池中模型，也可直接导入、删除临时模型。只有“入池”或删除永久模型时弹出管理员口令窗口，输入口令并确认后才提交该操作；选择、查看永久模型无需口令。口令仅用于本次请求的 Authorization 请求头，提交或取消即清空输入，不写入模型、URL 或浏览器本地存储，也不会随之后的临时操作发送。
- 选择本地 JSON 文件或点击“导入 JSON”，校验成功并保存后进入临时组、加载该模型；“入池”将选中的临时模型移到永久组，记录入池时间。修改输入区 JSON 后需先导入为新临时模型。临时模型同样共享并持久保存，不随关闭页面自动清理。
- 删除的是下拉框选中的共享条目：临时模型直接删除，永久模型在口令窗口确认后删除。删除后加载剩余池的默认模型；同名模型以条目 ID 区分，不相互覆盖。入池只变更存储分组，不重置当前模型的运行状态。关闭后重新打开管理窗口会读取最新列表；若其他设备已删除当前条目，列表和场景一起切换到剩余默认模型。
- 每次共享写入提交当前 `revision`。其他设备已修改池时返回 HTTP 409，刷新列表并提示核对后重试，不自动重放操作。共享写入未经响应确认，不预先修改服务器记录；断线后保留现有快照与当前模型，不静默换成旧示例。
- 后端连接失败时只禁用“入池”和“删除”，保留文件/JSON 导入、模型切换、编辑、下载和关闭。导入的合法模型直接加载到场景，放入当前页面的临时组并标注“本页临时”。如果一开始连示例文件也读取失败，仍可从空池导入。
- 本页临时模型保存在页面内存中，关闭再打开管理窗口时保留；刷新整个页面会丢失，可先下载保存。重新打开管理窗口会尝试连接后端；恢复连接后保留本页临时模型，不自动上传。对本页临时模型点击“入池”并输入口令后，先上传到共享临时组，再移入永久组；若后一步失败，保留已取得的共享条目 ID，重试不会重复上传。在线时删除本页临时项只移除本页记录。
- 导入过程中网络中断或服务器不可用时，仍把合法 JSON 保留为本页临时模型，提示共享保存未确认；连接恢复后需核对池中记录。读取和写入请求分别最多等待 5 秒和 10 秒，避免连接故障一直阻塞窗口；口令错误和版本冲突不作为断线处理。
- 保留原模型的字段、旧 ID 写法、`tag`、`outputDisplay` 和 MD5，不重新计算 MD5；模型池条目 ID、时间和版本号在模型外保存。节点级异常继续使用原有隔离规则。

## 共享模型池格式

Sites 项目 R2 中的 `model-pool.json` 与本地 `public/example.json` 使用以下相同结构，原示例保存在永久组。旧版单模型文件仍可读取，首次成功管理写入后保存为分组结构；模型内部的原字段与渲染配置继续保留。

```json
{
  "version": 1,
  "revision": 0,
  "temporary": [],
  "permanent": [{
    "id": "example",
    "createdAt": "1970-01-01T00:00:00.000Z",
    "promotedAt": "1970-01-01T00:00:00.000Z",
    "model": {
      "name": "示例模型",
      "nodes": [{"id": "Q0", "ex": "J0K(X0)"}],
      "initial_q": {"0": [], "1": []},
      "q_y": [{"Y0": "Q0"}]
    }
  }]
}
```

新导入条目使用唯一 ID、服务器创建时间，临时组的 `promotedAt` 为 `null`。每次实际修改递增池的 `revision`；原示例的零时间表示迁移种子，并非推断其实际创建日期。

## Sites Worker 与 R2

线上沿用现有 Sites 项目及访问范围。`.openai/hosting.json` 声明 `r2: "BUCKET"`，Sites 自动提供项目所属的 R2 存储；服务端通过 `cloudflare:workers` 的 `env.BUCKET` 读写唯一的 `model-pool.json`。不需要个人 Cloudflare 账户、R2 Access Key 或 S3 SDK。前端仍使用原 `/api/model-pool`，所有 3D、计算、图像提取、输出画板、模型管理和下载功能保持原样。

- 首次读取时，如果 R2 中还没有 `model-pool.json`，用随应用打包的现有 `public/example.json` 初始化。创建必须带 `If-None-Match: *`，两个首次请求竞争时只允许一方创建，另一方读取已创建结果。已有文件、后续更新与重新部署不会被种子覆盖；读取异常、损坏 JSON 不触发重新初始化。
- 保存时从同一次 R2 读取获得 JSON 和 ETag，核对客户端 `revision` 与最新分组权限，再以 `onlyIf: { etagMatches: 原ETag }` 条件写入。即使两个 Sites 请求同时读到同一版本，也只能一个写入成功；另一方收到 HTTP 409，界面刷新后提示核对再试，不自动重放。ETag 仅参与存储比较，不改写原模型 MD5，也不加入 JSON。[R2 条件写入规则](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)
- 临时导入和删除保持公开，入池和删除永久模型仍要求管理员口令。`MODEL_POOL_TOKEN` 在 Sites 项目中作为服务端密钥设置，不进入前端产物、模型 JSON 或托管清单；`MODEL_POOL_ALLOWED_ORIGINS` 是可选的完整来源白名单，同源默认允许。
- R2 不可用或保存结果未确认时，保留原来的断线处理：导入、切换、编辑、下载仍可用，入池和删除暂时禁用。`/example.json` 同样返回当前 R2 模型池，不返回旧构建快照。浏览器读取使用 `no-store`。

构建会生成 `dist/client`（原 Vite 前端）、`dist/server/index.js`（Sites Worker）和 `dist/.openai/hosting.json`（R2 绑定声明）。Sites 按 Worker 应用发布，不再使用不支持运行时存储的纯静态托管配置。`server/sites-worker.js` 是线上入口；源码只声明逻辑绑定，由 Sites 创建和连接实际存储。

## 本地服务与配置

`./dev.sh build` 构建完整 Sites 产物。`./dev.sh serve` 提供本地页面及模型管理调试，默认访问 `http://127.0.0.1:4173`；本地池保存于被 Git 忽略的 `server/.data/model-pool.json`，首次读取时从种子创建。开发时分别启动 `./dev.sh api`（5174）和 `./dev.sh`（5173）。`./dev.sh preview` 预览前端构建产物，沿用 `/api/model-pool` 到本地 5174 端口的代理；未启动 API 时仍支持本页导入和下载。预览不启动 Sites Worker。

前端默认请求相对路径 `./api/model-pool`；`VITE_MODEL_POOL_API_URL` 可在开发或构建时覆盖该地址。默认本地配置连接 Node.js 服务和本地池，不连接线上 R2。

本地可在 `server/.env` 设置 `MODEL_POOL_TOKEN`，已有环境变量优先。Sites 线上密钥独立配置；不需要 S3/R2 Access Key 配置；本机环境文件保持本地。

数据校验与变更仍由 `src/models/model-pool.js` 负责；`server/model-pool-service.js` 让本地和 Sites 共用版本与权限检查，`server/model-pool-api.js` 提供线上 HTTP 接口，`server/sites-r2-store.js` 封装绑定读取、首次迁移和条件写入。专项测试覆盖模型与渲染字段保真、权限、并发冲突、迁移竞争和失败恢复；不以这些测试代替全部 3D 功能验收。单次 API 请求仍限制为 32 MiB。

## 预览与发布边界

本地开发、构建、预览和 `serve` 均不部署线上 Site；默认本地 API 配置不更改线上 R2。`public/example.json` 是迁移种子及本地预览快照；生产构建不会把它作为 `/example.json` 静态文件覆盖 Worker 返回的当前模型池。

Sites 云端版本保存与部署是独立操作。部署前需基于当前发布授权执行；上传完整项目源码同样遵循明确的传输授权。`.openai/hosting.json` 保留项目身份和逻辑绑定。不要将旧静态预览报告视为当前 Worker 发布说明。

最终 HTTPS 环境的 WebGPU、Worker、资源类型、文件选择、下载和全屏权限需在实际环境验证；本地构建或模拟测试不能代替线上验收。
