# ModelShow 的 JKRD V4.0.0 实现

[返回项目入口](../README.md) · [操作说明](usage.md)

唯一计算契约是 [JK 项目的 JKRD V4.0.0](../../JK/docs/JKRD.md)。本页只说明 ModelShow 的实现位置、接口与验证边界，不独立定义规则。入口见 [JK_SOURCE.json](JK_SOURCE.json)。原中央 `docs/projects/ModelShow.md` 已不存在，本项目不继续引用该失效路径。

## 实现与职责

| 入口 | 职责 |
| --- | --- |
| `src/jk/model-schema.js` | V4 结构、全部来源 DAG、来源/被引用数量、输入副本、输出绑定、端口、统计、FIFOS 与双指纹校验；显式构建和序列化 |
| `src/jk/engine.js` | 同步原子 EX、即时传播、两条任务队列、每目标 Qi_J0 到达集合、状态及队列保存边界 |
| `src/ui/playback.js` | 暂停、单步和每帧计算预算；每次只调用一个完整任务，不提供另一套计算语义 |
| `html/main.js` | 外部 send 输入交接、Yi 事件显示、队列/节点详情和下载入口 |
| `src/jk/model-pool.js`、`src/ui/model-manager.js`、`html/server/` | 文件、JSON、模型池、HTTP/R2 均复用完整快照校验；旧数据不自动转换、不主动覆盖 |
| `src/ui/output-display.js`、`src/ui/output-display-ui.js`、`src/scene/` | Yi 数据聚合、画板配置与绘制、网络显示、布局；不生成新的 Qi 任务 |

## 结构入口和拒绝边界

`compileSnapshot(raw)` 是公共导入入口，只接受 `format="jk-logic-structure-V4.0.0"` 的完整快照。字段、类型、编号、状态、引用、队列、统计与两个指纹全部校验后才允许替换当前模型。拒绝旧 format、旧 `propagation`、节点 `tag`、顶层 `outputDisplay`、缺失 `FIFOS`、未知字段和旧指纹；不补空队列或重算指纹以绕过导入检查。

`compileModel(raw)` 保留诊断行用于内部检查；任一结构错误都会阻止整个模型运行。`serializeModel(raw, options)` 是明确的 V4 构建入口，可以由合法的 `nodes + initial_q + q_y` 新结构生成元数据；它不是旧快照迁移工具。输入副本必须明确声明在 initial_q 中，构建器不猜测或自动补入节点。

校验与中央契约对应：

- Xi 只允许被同编号有状态 Qi 的固定 `J0K(Xi)` 引用，后续节点只读取 Q。
- 节点只允许 `id`、`ex`、可选 `pro`。无状态节点从 J0 起算且不能自引用；合法有状态自引用仅提供固定参数。
- 全部 Q 连接排除合法自引用后必须为 DAG。不存在“编号较大状态来源不可读取”的旧限制。
- `ex_source` 对不同非自身来源计数；EX 操作总量仍逐 token 计数。每个 Q 至少被一个其他 Q 或 Yi 引用。
- Yi 只能绑定默认或显式 `pro="q=0/1"` 的已有 Q。输入/输出均为连续身份映射，各不超过 216 位。
- FIFOS 两队列都必须存在；锁存数据恰好覆盖目标的全部 Qi_J0 参数，队列归属、顺序和重复项受校验。

## 运行与页面交接

`send(data)` 要求非空对象，仅接受已声明 Xi 的数字 0/1。先完整校验，再按 Xi 数字编号逐项更新外部值并向 `Xi.FIFO` 加入复制任务。暂停不阻止输入；同值、同目标任务都保留。未知端口会使本次提交整体失败。

`step()` 从固定优先值 1 的 `Xi.FIFO` 取一个任务，只有该队列为空才从优先值 5 的 `Qi.FIFO` 取。读取全部参数后完整计算 EX、提交一次 q、即时处理所有直接目标与输出，再返回给界面。单步不会递归执行后继 EX。

Qi_J0 到齐时立刻锁存到新任务并清空当前集合，下一组数据不影响旧任务。未收齐的数据可跨 send 保留；重复来源在未完成集合中覆盖同一槽。Xi、有状态来源 q、自身显式 Q 参数均在任务开始时读取并固定。来源自引用不建立事件关系。

首次输入前 Xi 不可读。恢复的输入复制任务仍保留，出队时没有可读 Xi 才结束，连 J0 也不执行；Xi=0 是有效输入。页面以“参数不可读 · 已结束”区分这类任务，节点求值次数和 EX 操作次数不增加。

## 输出和可视化

Yi 显示最近一次实际事件的数据。初始化或恢复时为“未输出”，不从已保存 q 伪造输出。零值与同值发布都形成独立事件；队列排空不会产生新输出，也不会让不同 Yi 强制同步。节点详情中的当前 q 与最近发布值分开显示。

队列面板按下一次选择顺序展示两条队列，显示队列名、目标 Q、任务序号和锁存数据。任务序号仅用于当前页面追踪，不写入标准快照。面板虚拟滚动不裁剪计算任务；历史最多保留 400 条，显示最近 60 条。逐帧最多处理 10,000 个任务并遵守时间预算，未处理的任务留到下一帧；这个调度预算不是队列容量或业务存储容量。

页面结构和变长行模板在 `html/index.html`，固定样式在 `html/style.css`。默认值、展示限制和固定队列优先值集中在 `html/config.js` 冻结的 `APP_CONFIG` 树中。JS 只克隆模板、更新数据和绑定事件。

## 快照、指纹和恢复

`JKEngine.capture()` 在同步任务边界同时复制有状态 q 与未执行任务；`snapshot()` 据此生成完整 V4 快照。当前 EX、全部传播及一次 send 的更新入队均为同步操作，浏览器下载事件只会在这些完整操作之间运行。每个任务返回后播放控制器才可能选择下一个任务。

指纹直接使用中央 JKRD 的字段组合与规范化规则；`format_md5` 包含实际 initial_q 保存值，`md5` 还包含 FIFOS 和 created_at。规范 JSON 递归排序对象键、保留数组顺序，省略默认 pro；不会对队列排序、合并或去重。中央示例的原始两个指纹由自动测试交叉核验。

下载当前已加载模型时保存当前 q、队列、`display.show` 与已应用的 `display.outputBoard`。未导入草稿保存自己的状态、队列和画板，不借用当前运行实例；明确编辑结构时重新生成统计与指纹，仅伪造元数据或指纹则拒绝。模型池中的原记录不会随运行状态或画板编辑自动改写。

恢复只还原标准字段。Xi 当前值、无状态临时结果、未收齐到达集合、Yi 事件历史和动画进度不保存。因此 V4 快照能恢复待执行任务，但不是完整运行现场检查点。页面“重载”恢复加载快照中的 q 与 FIFOS，清除本次会话输入和显示记录，保持暂停。新加载带待执行任务的快照也先保持暂停，明确继续或单步后才消费任务。

## 画板与扩展设计

按用户于2026-10-14确认的保存方式，ModelShow 在快照的 `display` 内增加可选 `outputBoard`，与 `show` 并列。中央 JKRD 当前列明 `display.show`；`display.outputBoard` 是本项目展示扩展，未修改中央规则，也不表示其他消费者已支持此字段。画板只接收 Yi 数据，不改变计算语义；整个 `display` 仍不参与两个指纹。

`display.outputBoard` 保存完整画板对象：version、enabled、rows、cols、scale、pixels；复用画板校验，scale 必须显式提供。导入快照时恢复画板，缺少该可选字段时使用统一默认画板；无效画板拒绝导入，不替换当前模型。画板应用后的配置直接同步到模型管理的“模型 JSON”，只合并 `display.outputBoard`，保留其他手工编辑；未应用的灯编辑草稿不写入。输出渲染窗口不再提供导出区域，通过模型管理统一查看、复制、导入和下载。同步画板不修改模型池原记录；手工编辑导致 JSON 暂时无效时保留原文，修正后再补入待同步画板。

动态节点创建、连接、释放和按需扩展等待区仍按中央 JKRD 的扩展设计边界处理。静态任务队列不提供每次 Xi 的历史保存，连续输入的多个任务可能读取同一个最新 Xi；本实现不将计算队列或显示历史宣称为动态业务存储。

改动对照及本次实际验证见 [V4 对齐记录](validation/jkrd-v4-2026-10-12.md)。历史验证保留原日期和原范围。
