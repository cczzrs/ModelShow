# 模型格式与执行语义

[返回项目入口](../README.md) · [操作说明](usage.md)

## JK 节点：

### JK 节点状态有两种：节点类型的判定依据：以 initial_q 为准

- 有状态节点：该节点始终存储一位 bit 数据 q = 0/1，q 会在模型初始化时被赋值且计算 ex 序列后写回 q 被更新
- 无状态节点：该节点不存储数据。只计算 ex 序列，完成后发布结果，不保存为下一次执行的起始状态。

### JK 节点有四种操作标识：
- `J0`: 置0
- `J1`: 保持
- `K0`: 保持
- `K1`: 翻转

### 操作标识会按顺序组合表达出 ex 计算序列在 JK 节点中：

#### 表达组合逻辑 ex：

- `Jx`: `q AND x`
- `Kx`: `q XOR x`
- `q = 0 = J0`
- `q = 1 = J0K1`
- `NAND(a,b) = J0K1J(a)J(b)K1`
- `NOR(a,b)  = J0K1K(a)J(b)K1K(a)`

- 只支持 J0、J1、K0、K1、J(X编号)、K(X编号)、J(Q编号)、K(Q编号)，按顺序拼接；Q 引用也接受与节点声明一致的兼容标记写法，例如 `K(Q215L9B7)`，详见“JK 节点固定 ID 与标记”。允许忽略空白，不允许嵌套表达式，空表达式和未识别字符均报错。解析器必须消费完整字符串，不能只提取其中合法的片段继续计算。

#### ex 计算序列触发事件：
- 当前节点的任一`无状态节点的参数`到达时都先保存更新该节点对应的临时参数(覆盖最新值)（如有）。一次到达同时满足多处相同引用。所有临时参数都持续保留，直到到齐`触发执行`。
- 一次发布对同一目标只投递一次来源事件，同时满足多处引用；多条展示线不能额外增加执行次数，
- 当前节点的任一参数到达时都检测是否还有任一`无状态节点的参数`未到达，只有没有的时候才`触发执行` ex 计算序列求值。
- 当前节点没有`无状态节点的参数`每次参数事件都`触发执行` ex 计算序列求值，包括值未变化的事件，
- 当前节点只包含常量就只在初始化时执行
- ex 序列中无状态来源参数读取当前队列项保存的不可变副本；有状态来源参数在执行时读取其当前 q 值（沿线携带的值未必等于最终参与运算的值）。
- 无状态 JK 节点的 ex 必须以 J0 开头，否则标记异常并禁止执行。输入节点不受此限制。

#### 逻辑执行顺序 - `执行队列`

- `执行队列`中的节点都是`触发执行`且未执行的待执行节点，每执行完一个节点后就传递计算后的值到所有引用该值的节点，就会产生一批新的待执行节点按id编号大小排序后追加到队列尾，按队列顺序执行。
- 同一个节点如再次满足`触发执行`可以重复入队。同一节点重复触发时，保留多次执行即多次入队
- 节点入队后复制所有`无状态节点的参数`的到达值，且无法被修改，清空该节点保存的所有`无状态节点的参数`临时参数（如有）
- 当执行该节点时，才读取有状态节点 q 值（如有）
- 取出队首 → 读取参数并计算 → 写回有状态节点的 q → 向引用节点投递结果 → 将新触发项按节点编号数值排序追加到队尾。
- 单个队列项的计算、写回和结果投递不可被新输入打断；发送操作在两个队列项之间处理。
- 显示完整的`执行队列`列表及 当前队列长度
- 显示累计所有节点执行总次数。每个节点旁边显示该节点的执行次数。
- 网络概览的“EX 总量”（`stat-ex`）统计所有 JK 节点的 EX 操作项总和：每个 J/K 操作计一项，包含常量和重复引用，例如 `J0K(X0)K1` 为 3 项。加载模型时统计，发送信号、单步和重载不会改变；导入另一模型时更新。表达式可完整解析的异常节点也纳入统计，无法解析的 EX 不计入，并沿用节点异常提示。
- 页脚 `EXtotal` 显示所有已完成节点求值的 EX 累计操作总数：每个 J/K 操作计一次，包括 `J0` 等常量操作及重复引用。例如 `J0K(X0)K1` 每次求值增加 3；仅发送输入、等待入队或发布 Yi 不增加该数。多次发送持续累加，重载或导入另一模型时清零；普通播放、跳过动画和单步使用相同统计规则，随界面在帧尾刷新。

### JK 网络模型 JSON 格式：
```json
{
  "name": "对当前 JK 节点组的描述",
  "md5": "e46627f52ca9a3974fddc75020b20ef0",
  "format": "jk-logic-structure-V3.1.0",
  "format_md5": "b1b11868c091bfa5e571935200467312",
  "created_at": "2026-08-22T04:1787372535000000000",
  "input_bits": 4,
  "jk_bits_max": 16,
  "jk_bits": 6,
  "output_bits": 4,
  "ex_source_max": 3,
  "ex_operation_max": 5,
  "ex_source_sum": 12,
  "ex_operation_sum": 23,
  "nodes": [
    {"id": "Q0", "ex": "J0K1J(X0)K1"},
    {"id": "Q1", "ex": "J0K1J(X1)K1"},
    {"id": "Q2", "ex": "J0K1J(Q0)J(Q1)K1"},
    {"id": "Q3", "ex": "J(X0)J(X2)K(Q0)"},
    {"id": "Q4", "ex": "J0K1J(Q2)K(X1)"},
    {"id": "Q5", "ex": "J(X3)J(Q1)K(Q3)"}
  ],
  "initial_q": {
    "0": [],
    "1": ["Q3", "Q5"]
  },
  "q_y": [
    {"Y0": "Q2"},
    {"Y1": "Q3"},
    {"Y2": "Q4"},
    {"Y3": "Q5"}
  ],
  "inputs": [
    {"X0": "X0"},
    {"X1": "X1"},
    {"X2": "X2"},
    {"X3": "X3"}
  ],
  "outputs": [
    {"Y0": "Y0"},
    {"Y1": "Y1"},
    {"Y2": "Y2"},
    {"Y3": "Y3"}
  ]
}
```
JK 网络的节点、状态和输出映射由 `nodes`、`initial_q`、`q_y` 决定；输入 Xi 从表达式引用中提取，未引用的输入不显示。其它原始元数据在导入和导出时保留；可选 `outputDisplay` 单独控制输出画板，不改变 JK 执行。

### JK 节点固定 ID 与标记

- **固定 ID 决定节点身份**：`id` 使用 `Q` 加非负十进制整数，不允许前导零，例如 `Q0`、`Q215`。同一模型中固定 ID 必须唯一。
- **`tag` 只用于描述与显示**：可省略；提供时必须是非空字符串，以英文字母开头，后续仅包含英文字母或数字，大小写敏感，例如 `L9B7`。`{"id":"Q215","tag":"L9B7"}` 在界面显示为 `Q215L9B7`，详情分别列出固定 ID 和标记。标记不参与触发、求值、排序或布局推导，不会把 `L9B7` 自动解释为层号或位号。
- 节点编号按数值排序，比较使用 BigInt，支持超过 JavaScript Number 安全整数范围的编号。常量节点初始化入队、同源触发目标及按编号排列的布局都忽略标记。

推荐将 ID 与标记分开保存，表达式、初始化和输出映射使用固定 ID。以下模型中 `Q215` 是初值为 0 的有状态节点：

```json
{
  "name": "带标记的状态节点",
  "nodes": [
    {"id": "Q215", "tag": "L9B7", "ex": "K(X0)"},
    {"id": "Q216", "ex": "J0K(Q215)"}
  ],
  "initial_q": {"0": ["Q215"], "1": []},
  "q_y": [{"Y0": "Q216"}]
}
```

兼容旧式尾缀 ID：导入 `Q215L9B7` 时，编译结果拆分为固定 ID `Q215` 和标记 `L9B7`。上例也可以写为：

```json
{
  "name": "带标记的状态节点",
  "nodes": [
    {"id": "Q215L9B7", "ex": "K(X0)"},
    {"id": "Q216", "ex": "J0K(Q215L9B7)"}
  ],
  "initial_q": {"0": ["Q215L9B7"], "1": []},
  "q_y": [{"Y0": "Q216"}]
}
```

- `ex`、`initial_q` 和 `q_y` 均接受固定 ID，或带有该节点所声明标记的引用；解析后统一使用固定 ID。例如声明 `L9B7` 后，`Q215` 和 `Q215L9B7` 指向同一节点，而 `Q215L9B8` 报引用错误。无标记节点只接受固定 ID 引用；不存在的编号仍报错。
- 同一个节点定义同时提供尾缀 ID 和 `tag` 时，两处标记必须完全一致，否则该节点异常。`Q215`、`Q215L9B7`、`Q215L9B8` 若作为多个节点定义同时出现，属于固定 ID 重复，不合并、不覆盖。异常节点及依赖它的部分禁止执行，独立合法部分继续运行。
- 非常量来源在引用归一化后去重：`K(Q215)K(Q215L9B7)` 只等待同一来源的一次到达和一次逻辑通知；两项 K 操作仍按原顺序分别求值、分别计入 `EXtotal`，展示线仍保留两条。
- 运行状态、缓存、队列和连线使用固定 ID；场景名称、节点按钮、队列、历史和输出来源显示完整名称。编译结果保留原始 ID，导入归一化不改写原始模型；“导出模型及画板配置”保留原始 ID 写法、`tag`、其它模型字段与原 MD5，仅写入画板配置。

### 模型包含三类节点：

- 输入节点 `X0..Xn`
- JK 节点固定 ID `Q0..Qn`，可附带独立 `tag`
- 输出节点 `Y0..Yn`

## 初始化、异常与执行边界

先建立所有节点和引用关系，赋值持久 q，再将常量节点按编号加入队列。初始化 q 不发布事件。表达式非法、引用不存在、固定 ID 重复、初始化冲突的节点保留展示并标明异常；它们及其依赖部分禁止执行，独立合法部分继续运行。

一次发送按 Xi 编号数值顺序投递全部有效输入，再继续执行队列。发送可插入两个完整队列项之间；没有轮次、批次、组次等额外计算语义。对目标 JK 节点而言，输入 Xi 和无状态 JK 发布的值都属于需要缓存并收齐的临时参数；有状态来源在实际求值时读取当前 q。输入 Xi 自身不等待参数，也不进入执行队列。

输出 Yi 收到来源发布后更新最近值，不进入执行队列；尚未收到值显示“未输出”。动画消费同一份事件记录，只展示已发生的输入投递、求值和传播，不能重新触发计算。记录保留来源、目标、传输值和求值前后状态。

### 输入节点数据 JSON

```json
{"X0": 1, "X1": 0, "X2": 1, "X3": 0}
```

#### 缺失输入或未匹配到的输入节点数据，输入节点是无状态节点类型，不参与本次发送

- 已匹配输入的值必须为数字 0 或 1；出现非法值时提示错误，本次发送不投递任何输入。

## 示例执行

对上面的六节点JSON发送 `{"X0":1,"X1":0,"X2":1,"X3":0}`，执行顺序为 `Q0 → Q1 → Q3 → Q2 → Q5 → Q4`，各节点发布值依次为 `0、1、1、1、1、1`，最终四个Yi均为1。这是该明确模型的期望，不适用于用户已经修改过的共享池默认条目。
