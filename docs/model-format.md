# ModelShow 的 JKRD7 实现

[返回项目入口](../README.md) · [使用说明](usage.md)

唯一规则来源为 [JKRD7（7.0.0）](../../JK/JKRD7.md)。本文只记录 ModelShow 的实现接口与范围，不另行定义规则。中央依赖见 [JK_SOURCE.json](JK_SOURCE.json)。

## 三种独立文件

| 文件 | 内容 | 用途 |
| --- | --- | --- |
| JKM 定义 | `jkm`、`version`、`queues`、`roots` | 保存结构和初值；all 节点的 `runtime.trigger_all` 全为 null |
| 运行脚本 | `run`、`model`、`observe`、`batches` | 保存输入时序与输出观察方式，格式见 JKRD7 §9.4 |
| 现场快照 | `snapshot`、`jkm`、`version`、`q`、`trigger_all`、`rounds`、`queues` | 保存处理单元之间的全部运行状态，格式见 JKRD7 §9.5 |

下载模型保存 JKM 定义，不把当前 q、队列、界面布局或画板配置塞入 JKM。续算需另存现场快照，同时保留对应定义和观察配置。模型名称用于检查快照归属，不是结构指纹；恢复时应使用同一份 JKM 定义。

旧 `format`、Xi／Yi、`nodes/ex` 字符串、`initial_q`、`FIFOS`、MD5 元数据和 `display` 扩展均不是本版格式，不提供转换入口。

## 校验入口

`src/jk/model-schema.js` 的 `compileModel(raw)` 校验通过后返回索引；失败抛出带 `errors` 数组的 `ModelValidationError`。文件导入、编辑器加载、模型池读取与写入共用此入口。

校验覆盖：

- 只接受 7.0.0 和获准字段；bit 必须是数字 0 或 1，拒绝字符串、布尔和 null。
- JKI／JKS 完整结构、同层唯一 ID、短引用和绝对路径、全部 sources 与 trigger 引用、七种 publish 模式。
- JKI.all 定义中全 null 的到达记录；空 EX 不因 s 或 seed 存在而变为计算任务。
- JKS 登记的非空数组、跨类型去重、实际成员关系；同一 JKI 被多个 JKS 登记按中央 §9.3 拒绝。
- 事务范围内触发来源限制、事务范围无环、纯通知环拒绝。事务范围外带 EX 的环允许存在，运行预算不等于终止证明。
- `pro.jksid` 解析到真实 JKS；`pro.tag` 只用于展示，不参与身份与行为。

`validateRunScript(script, compiled)` 与 `validateSnapshot(snapshot, compiled)` 分别校验独立文件。快照须匹配模型，准确覆盖所有 q，保存尚未到齐的 all／轮记录，并使用合法且归属正确的事件与任务。无效输入批、脚本或快照不能部分修改当前状态。

## JavaScript 与 WebGPU

`src/jk/engine.js` 实现 JKRD7 §4—§7。每个 queue 有独立的事件 FIFO 和任务 FIFO；当前执行器只处理实际使用一个 queue 的模型。事件优先，订阅者按绝对路径逐段排序：同层 Q 在 G 前，同类按数字编号比较。

一次节点任务在入口固定所有来源 q，执行 J（AND）与 K（XOR），按 publish 判定通知，再写入结果。通知只含来源路径，不携带 q 或 result。空 EX 立即判定发布，不创建任务，也不应用 seed。all 的重复到达记录遵守 null → 0 → 1，齐备后立即清空。

JKS.all 按本轮首次到达顺序放行；transaction 到齐后入队，transaction_any 每条通知入队。事务局部推进到静止后统一提交范围外投递。子孙事务在活动祖先事务内就地放行，不额外创建事务任务。一个事务是不可穿插的处理单元。

默认 JavaScript 路径按串行顺序计算。WebGPU 仅计算合格节点批的 EX：目标互异，后方任务的 sources 不读取批内前方任务目标。批结果按原任务顺序发布、写 q，并先处理事件再继续提交后续任务，保证标准记录与串行参考一致。事务内采用同一规则。GPU 执行期间不接受会穿插当前处理单元的输入或快照操作。

页面每帧预算只限制调度时间，不丢任务。GPU 批在主队列投递事件达到预算后，于完整事件边界返回，尚未提交的节点任务放回原 FIFO 顺序；下一次执行重新读取入口值。通用异步计算回调若在事务中抛错，阻止继续执行与导出半事务现场，只能重置或恢复合法快照；这不是新增业务回滚规则。

计算设备与场景渲染设备是不同职责。场景改用 Canvas 2D 不改变计算平台。计算 WebGPU 不可用或派发失败时，界面明确报告改用 JavaScript；尚未提交的整批从同一份入口值重新计算，不使用已经完成的部分 GPU 结果，也不改变事务提交顺序。场景 GPU 成功不代表计算 GPU 已验证。

## 输入、输出和记录

外部输入只向已登记的空 `trigger.any` 入口追加通知，不写 q。输入值通过独热入口表达；例如一个 bit 使用置 0、置 1 两个入口。重叠输入放在同一批，批内顺序保留，不去重。

运行脚本从定义初值开始：静止时注入一批，执行到静止，再处理下一批。浏览器使用当前已加载的 JKM，要求脚本 `model` 与页面登记的文件标识一致；它不读取任意本机仓库路径。

输出模块订阅 watch 成员，在通知真正投递时按 read 数组顺序读 q。事务内通知要等提交后才到达输出模块。初始化、修改布局或队列排空不会伪造输出。

标准 JSONL 记录仅有 `inject`、`notify`、`q`、`output`，与中央 §9.4 一致。页面只展示有限行，下载读取完整记录。处理单元数、GPU 批次与事务标记是展示信息，不加入标准记录。

## 快照与边界

快照只能在完整处理单元之间捕获，不能保存半个事务。它包含所有 q、不全为 null 的 all 到达记录、非空登记轮与待执行双 FIFO；事务提交事件保留 `to` 和 `out`，避免恢复后重复向范围内投递。

恢复前先校验整份快照，校验通过后再替换运行状态。输出历史、已产生的执行记录、观察配置和布局不属于快照字段；恢复后保持暂停，继续执行产生新的记录。观察配置须与保存快照时一致。

中央工厂模块仍待适配；本项目没有添加生命周期删除、自动故障回滚、多 queue 调度或旧版迁移规则。验证证据、状态快照及过程报告存放在系统临时目录，记录须保留原日期、协议版本、实际覆盖范围和未验证事项；不能将未覆盖的路径视为已经通过。正式测试源码保留在 `tests/`，产品文档保留在 `docs/`，详见[留档管理](development.md#留档管理)。
